# Talash Web

Talash is a LinkedIn + Fiverr style network for Pakistani students and fresh graduates. This first slice is a complete, browser-friendly product preview with demo data and Supabase-ready service boundaries.

## Run it

```bash
npm install && npm run dev
```

Open [http://localhost:3000](http://localhost:3000). No environment variables are required for the demo preview. For Supabase auth and storage, copy `.env.example` to `.env.local`, add the project URL and anon key, then create the tables described in `supabase/schema.sql`.

## Product map

- `/` landing page with SEO metadata and motion-led product story.
- `/auth` role-aware, three-step password sign up and password login UI. Students are checked for a `.edu.pk` or `.ac.pk` address. OTP helpers remain in `lib/auth/verification.ts` for later re-enabling.
- `/dashboard` is the authenticated workspace entry point; `/app` remains available for the demo workspace.
- `/admin/team` is protected by middleware and a server-side profile role check. Only `profiles.role = 'Admin'` is accepted.
- `/api/ai` exposes server-only profile analysis, bio writing, and gig helper features. Requests are limited to 10 per user per hour.
- `/sitemap.xml` and Open Graph metadata are generated by the App Router.

## Architecture

The `app/`, `components/`, `lib/`, `services/`, and `types/` folders stay intentionally small. Demo data lives in `lib/demo-data.ts`; Supabase setup lives in `lib/supabase.ts`; payment providers implement `services/payments.ts`. The mock payment provider applies the 10% Talash fee, while JazzCash and EasyPaisa adapters are documented stubs.

## Supabase notes

Enable email/password in Supabase Auth and add redirect URL `http://localhost:3000/auth`. Run the full `supabase/schema.sql` for a new project, or run its `alter table` statements for an existing project. Add `AI_API_KEY` only as a Vercel server environment variable; `AI_API_URL` and `AI_MODEL` are optional. Before production, add row-level security policies, upload validation, moderation workflows, and real payment webhooks. Badge eligibility is represented in the profile model: Blue Tick requires three months of activity plus review and is removed after one inactive month; Talash Badge requires one continuous year.
